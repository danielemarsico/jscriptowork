What it is

Windows Script Host runs JScript 5.8, an ES3-era engine that ships with every copy of Windows. It is always there, it needs no installer, and it is missing most of the JavaScript you are used to writing.

jscriptowork closes that gap. It is a small framework — a polyfill layer, a set of practical helpers, and a test framework — that makes cscript.exe usable for real automation work: reading files, calling HTTP APIs, driving Excel, hashing data, parsing CSV, and putting a native window on screen.

The whole point is what it doesn't need. There is no npm, no package.json, no node_modules, no transpiler and no runtime to install. A target machine needs nothing but Windows.

Quick start

Clone the repo (or download a release) and run a script through the launcher:

cscript.exe bin\launcher.js yourscript.js

Inside your script, pull in the libraries you need with load():

load("core");       // Array/String/JSON baseline
load("polyfills");  // Object, Number, Math, Date, Function
load("console");    // console.log / warn / error
load("system");     // files, stdin/stdout, HTTP

var users = JSON.parse(http_get("https://example.com/api/users"));

users
    .filter(function(u) { return u.active; })
    .forEach(function(u) { console.log(u.name); });

write_text_to_file("C:\\temp\\report.txt", "done");

One file to deploy

build.bat bundles every library and the launcher into dist\launcher.js — a single self-contained file, with dist\launcher.bat as a wrapper. Copy those two files to any Windows machine and they run as-is; no libs\ folder needed. 

build.bat
dist\launcher.bat yourscript.js

Libraries

Every library is a plain .js file under libs/, loaded on demand.

LibraryWhat it gives you
core.jsES5 baseline: Array/String basics plus Crockford's json2 (JSON.stringify / JSON.parse)
polyfills.jsExtended layer: Array, String, Object, Number, Math, Date, Function
console.jsconsole.log / info / warn / error / debug
log.jslog() levels (debug/info/warn/error) and a tee to a log file
system.jsstdin/stdout, file system, binary files, HTTP (sync, async and binary), date formatting
csv.jscsv_parse / csv_format, read_csv_file / write_csv_file — RFC 4180, no Excel required
helpers.jsInteractive prompts plus Excel / Access / Word COM automation
win.jsRegistry read/write, process listing and killing over WMI, command execution with captured output
crypto.jssha256, sha256_bytes, hmac_sha256
base64.jsbase64_encode / decode, over strings and over raw file bytes
ui.jsopen_hta(): native Windows GUI windows via mshta.exe, with live progress streaming
minimist.jsCommand-line argument parsing (vendored)
minitest.jsdescribe / it / assert / skip — the test framework the project tests itself with
ext.jsExt.encode / Ext.decode compatibility shim for older Ext-era code

What JScript still can't do

Missing methods can be polyfilled. Missing syntax cannot — it is a parse error, and it takes the whole file down with it. Write ES3 and reach for these workarounds:

Not availableInstead
let / constvar
Arrow functionsfunction () {}
Template literalsString concatenation
Destructuring, spread / restAssign properties manually; arguments
classPrototype-based patterns
for...offor or forEach
Default parametersCheck arguments inside the function
Promise / async / awaitCallbacks — see http_request_async()
?. and ??Explicit null checks
str[i]str.charAt(i)
setTimeout / setIntervalEverything is synchronous; sleep(ms)

The full list, with the runtime traps that go with it, is in the README.
